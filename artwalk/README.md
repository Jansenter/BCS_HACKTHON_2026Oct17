# 🎨 ArtWalk — Your Personal City Art Storyteller

Turn an ordinary walk into a cultural adventure. Hackathon MVP for **Downtown Vancouver**, built on the City of Vancouver Public Art Registry open data.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build → dist/
npm run preview    # serve the build
```

Node 20+ recommended. No API keys needed.

## What's in the MVP

| Feature | Where |
|---|---|

| **Artwork detail pages** — shareable artwork stories with source links and tour context | `src/components/StoryPanel.tsx` |

| **Tour progress** — mark visited, progress bar, completion screen with share, saved in LocalStorage | `src/lib/storage.ts`, `Completion.tsx` |
| **Personalized recommendations** — local recommendations use selected art interests and visits | `src/components/CommunityHub.tsx` |
| **Local demo profile** — save a display name, interests, and route preferences in this browser | `src/components/CommunityHub.tsx` |
| **Community suggestions** — submit artwork tips saved locally for a future review workflow | `src/components/CommunityHub.tsx` |
| **Accessibility preferences** — step-free, avoid-stairs, and quieter-stop preferences | `src/components/CommunityHub.tsx` |

Deep links work: `#/tour/waterfront?art=24` opens a tour straight at a story.

## Data pipeline

```
data/public-art.json  ──npm run data──▶  src/data/artworks.json   (138 Downtown works, cleaned)
```

`scripts/build-data.mjs` filters to `geo_local_area = Downtown`, `status = In place`, with coordinates; decodes HTML entities; and resolves artist IDs to names. Change `NEIGHBOURHOOD` in that script to target another area (e.g. `Mount Pleasant`, `Strathcona`).

### Honesty notes (the export has gaps)

- **Limited photos.** The export's `photourl` is empty. ArtWalk uses a deterministic generative cover (`ArtCover.tsx`) for most works; Angel of Victory, Untitled (Pair of Lions), King Edward VII Fountain, Sliding Edge, LightShed, The Drop, Digital Orca, Nike, Guru Nanak Jahaz, Weekend Chime, and A Parallax View use locally supplied images. Artwork detail pages link to the City registry, and the Angel of Victory photo credit links to the Vancouver Heritage Site Finder.
- **Artists are IDs only.** Names in `ARTIST_NAMES` were taken only from text inside the registry records themselves (each line cites the record). Three tour stops carry a `curatedArtist` credit, shown in the UI with a "curator credit" tag. Everything else honestly says "Artist not named in open data". To fill this in properly, merge the companion **public-art-artists** dataset from opendata.vancouver.ca in `build-data.mjs`.
- **Trivia never invents facts** — questions are generated from the record's material or installation year, and the answer cites the source field.
- **No account service or AI service is connected.** The profile and artwork suggestions are stored only in this browser. Recommendations are local, interest/visit based suggestions, not generated by an AI model; community entries are not uploaded or reviewed. Add a backend before treating these as shared accounts or public submissions.
- **Accessibility preferences are planning hints only.** The current walking geometry is standard walking directions or straight-line estimates. The registry does not include step-free access, curb cuts, surface quality, elevators, or crowd levels, so routes cannot be represented as verified accessible routes.

## Walking routes

By default the tour path is a dashed straight line between stops, with distances estimated (× 1.3 street-grid factor) and a link to OSM walking directions for each stop. For real street routing, copy `.env.example` to `.env` and add a free [openrouteservice](https://openrouteservice.org) key:

```
VITE_ORS_API_KEY=your_key
```

The route is fetched once and cached in LocalStorage, so the demo still works offline afterwards.

## Demo script (3 minutes)

1. Home → **Start "Waterfront Wonders"** — the whole route appears on the map.
2. Tap **Start here: Angel of Victory** → hit **Listen**; the transcript highlights as it reads.
3. Do the **Look closer** challenge, tap **Mark as visited**, then **Next stop →**.
4. Back on the list, tick the rest → completion screen with stats and **Share**.

## Neighbourhood exploration

Explore opens with all Vancouver neighbourhoods, each with a distinct boundary colour. Hover to see its name, then click to select it; the dropdown and artwork list stay in sync. The selected area has a thicker boundary and stronger fill. Choose a neighbourhood to filter markers and the list by polygon containment, or choose All Vancouver. My neighbourhood requests browser location and selects the containing area. Location requires localhost or HTTPS; manual selection works without location permission.

The 22 local areas use `src/data/local-area-boundary.json`. Yaletown and Gastown use explicitly approximate exploration polygons in `src/lib/neighbourhoods.ts`, not official administrative or heritage boundaries. Small areas take precedence for location detection; Downtown remains available as the broader area.

Additional in-place works are generated separately with `node scripts/build-data.mjs --city` into `src/data/city-artworks.json`. Existing `artworks.json` records take precedence by registry ID, preserving curated data and the existing photo mapping. The original data command and tours are unchanged.

## Evidence-based artwork tags

Explore offers **By BIPOC artists** (Black, Indigenous and people of colour) and **Indigenous Artwork** filters, separately from physical artwork types. Selected tags intersect with type, neighbourhood and search filters; both tags selected require both. Group works match BIPOC when at least one credited artist has documented identity. Indigenous Artwork covers documented Indigenous creators or explicitly described Indigenous works. Totem pole type alone is never used as identity evidence.

`src/data/artwork-tag-evidence.json` stores reviewed City artist biography excerpts and artwork records with source URLs. The City artist metadata was fetched from `https://opendata.vancouver.ca/api/explore/v2.1/catalog/datasets/public-art-artists/exports/json`. This is a verified subset, not comprehensive demographic data. Missing records remain unclassified. Add verified evidence to expand coverage; do not infer identity from names, appearance, birthplace, or references to Indigenous territory. Artwork details expose the evidence under “Artwork tags & sources.”

## Artist profiles and title corrections

`src/data/artists.json` contains the City's artist names, available biographies, country, website and source links for all artist IDs used by the current artwork files. Empty names in the artwork export are filled at runtime; existing curated names are preserved. Explore search includes the resolved artist names. Artwork details show an expandable artist section. Country is displayed as a registry field and is not used to infer identity tags.

To refresh from the official `public-art-artists` JSON export, run `python3 scripts/build-artists.py /path/to/public-art-artists.json`. This writes only `artists.json`. The damaged title for artwork #808 is corrected to **聚 Gathering**, credited to **Dawn Lo**, as confirmed by its City registry page and artist statement; the correction is also preserved by the artwork build script.

## Nearby places and optional AI picks

Artwork details include **Explore nearby with AI** with Coffee, Food and Explore categories, a 400 m / 800 m / 1.2 km radius, optional preferences, and up to three results. Numbered pins appear on the main map and a compact map inside the artwork panel (also visible on phones). Tapping a result or pin highlights the same place in both maps. Searches are centred on the artwork, not the visitor’s live GPS. Names, locations, cuisine and dietary/seating tags come from OpenStreetMap via Overpass or the independent Photon index; coverage and freshness vary. Distances are straight-line distances; the directions link opens a walking route. Venue hours, prices, quietness and accessibility are not verified.

`npm run dev` now serves the same-origin `/api/nearby` endpoint through a server-only Vite middleware. No additional npm dependencies or place-search key are needed. Without OpenAI credentials, actual mapped places are shown in distance order and explicitly labelled as such.

To enable AI ranking, put `OPENAI_API_KEY` and optionally `OPENAI_MODEL` (default `gpt-4.1-mini`) in `artwalk/.env.local`, using `.env.example` as a guide, then restart the development server. Never use a `VITE_` prefix for private keys or paste them into the frontend. The backend calls the OpenAI Responses API with structured output and `store: false`. It sends the category, user-entered preferences, and a limited list of mapped place facts. AI may only choose existing candidate IDs; unknown/duplicate IDs and invalid/incomplete responses fall back to distance order. It cannot generate venue facts or change links. No AI call is made when no places are found.

For production, run `npm run build` then `npm start` (Node 22+, default port 4173). This serves both `dist` and the API. `npm run preview` and static-only hosts do not provide the API; on a static deployment, host this endpoint separately behind a same-origin proxy. Keep API keys in host environment variables. The development server and production server load `.env.local`/`.env`; credentials are not bundled into client assets.

The service bounds request size, artwork IDs, categories, radius and preference length, rejects cross-site browser requests, rate-limits searches to 12 per minute per remote address, shares concurrent place searches and caches mapped results in memory for ten minutes. This is a hackathon service; multi-instance public deployments need a shared rate limit and authentication/budget controls appropriate to traffic. Requests start Private.coffee Overpass and hedge the main endpoint after 250 ms; each has a six-second timeout and the first complete response wins. An independent Photon category search starts after 500 ms with an eight-second timeout, so simultaneous Overpass outages do not block discovery. Photon results are filtered by category and the exact search radius, and missing venue details remain unknown. Provider failures are logged with their HTTP status or error. Set server-only `OVERPASS_URL` to use your own provider instead (disabling the public-provider fallbacks). Public Overpass can time out or rate-limit; the UI supports retrying and never fills failures with made-up businesses.

Run `npm run test:nearby` for provider-mocked server tests. Place lookups can be tested live without an OpenAI key; AI ranking must also be verified with a configured key before being described as live-tested.

Nearby search displays mapped results before optional AI ranking, with a five-second AI timeout. Repeated identical searches use a ten-minute browser memory cache as well as the server place cache. The client cancels obsolete requests when search fields or artworks change. When public providers are unavailable, a direct map-search link remains available; unsuccessful searches do not create pins for fictional results.

## Profiles, collections and personal walks

Open **My ArtWalk** from the home or Explore navigation and create a profile with your name. Artwork details include **Save to collection**, independently of visited status or likes. In My ArtWalk, choose at least two collected pieces, name the walk, reorder stops, and save. Open a saved walk to use the existing tour map, artwork stories and visited progress. Walks can be edited or deleted; removing a collected artwork does not remove it from saved walks.

Profiles, collections and walks persist in localStorage in the current browser. There is no sign-in service or cross-device sync. Accessibility preferences remain planning preferences, not verified route guarantees. Run `npm run test:profile` for profile/collection rendering, persistence readback, custom-tour stop order and navigation checks.
